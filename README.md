#  课堂分组信息填报系统

一个用于课堂场景的轻量级两人分组填报工具。学生打开网页填写两位同学的姓名并提交，
老师或同学可在同一页面上实时看到已填报的分组列表，并可按需删除错误记录。

后端使用 Flask 提供 REST API，数据以 JSON 文件持久化；前端为单文件页面，无需构建工具，
开箱即用。

## 功能特性

### 填报端

- **两人一组填报**：填写两位同学姓名后一键提交，自动生成组号与提交时间。
- **前端即时校验**：姓名为空、两人姓名相同会在提交前直接拦截并给出提示。
- **防重复提交**：提交过程中按钮自动禁用并显示"提交中…"，避免重复写入。
- **表单自动重置**：提交成功后清空输入框并聚焦到第一个输入框，方便连续录入。

### 列表与展示

- **实时列表**：展示组号、两位同学姓名与提交时间，顶部实时显示分组总数。
- **删除记录**：每组右侧提供删除按钮，删除前有二次确认。
- **空状态提示**：无任何记录时显示友好的引导文案。
- **响应式布局**：适配手机、平板与桌面，窄屏下自动调整输入框排布。

### 数据导出

- **一键导出 Excel**：运行 `python export_xlsx.py` 即可把 `groups.json` 导出为 xlsx 表格。
- **规范表头**：输出表头为 `序号 | 学生1 | 学生2`，按组号升序、序号连续编号。
- **只读操作**：导出过程不修改数据文件，服务运行期间也能安全执行。

### 安全与健壮性

- **XSS 防护**：所有用户输入在渲染前均经过 HTML 转义。
- **并发安全**：读写共用可重入锁，"读取-修改-写回"整体保持原子性。
- **原子写入**：数据采用"临时文件 + `fsync` + 原子替换"方式落盘，避免写入中断产生损坏文件。
- **损坏文件保护**：数据文件异常时**不会**降级为空数据，而是自动隔离备份并明确报错，
  防止历史记录被静默覆盖。
- **统一错误响应**：所有 API 错误均返回结构一致的 JSON，便于前端处理。

## 目录结构

```
ClassGroupInformationSubmissionSystem/
├── app.py          # Flask 后端：页面路由、REST API、数据持久化
├── index.html      # 前端单页：样式、表单、列表渲染与交互逻辑
├── export_xlsx.py  # 导出脚本：把 groups.json 转成 xlsx 表格
├── groups.json     # 数据文件（首次提交后自动生成，无需手动创建）
├── requirements.txt # 依赖清单
└── README.md       # 本文档
```

| 文件 | 说明 |
| --- | --- |
| `app.py` | 应用入口。包含存储层（`load_data` / `save_data`）、页面路由与 3 个 API 接口。 |
| `index.html` | 无外部依赖的单文件前端，由 `app.py` 通过 `/` 路由直接返回。 |
| `export_xlsx.py` | 命令行脚本，读取 `groups.json` 导出为 xlsx（表头：序号 / 学生1 / 学生2）。 |
| `groups.json` | 运行期自动生成，保存全部分组记录。程序会自动创建，无需手工新建。 |
| `groups.json.<时间戳>.bak` | 仅在数据文件损坏时自动生成的隔离备份，用于人工恢复。 |
| `groups.xlsx` | 运行 `export_xlsx.py` 后生成的导出结果。 |

## API 文档

所有接口均以 JSON 交互，请求体需携带 `Content-Type: application/json`。

### 数据结构

```json
{
  "id": 1,
  "name1": "张三",
  "name2": "李四",
  "created_at": "2026-09-16 10:00:00"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 分组编号，由服务端自动分配，从 1 开始递增。 |
| `name1` | string | 第一位同学姓名，去除首尾空白，最长 20 个字符（前端限制）。 |
| `name2` | string | 第二位同学姓名，规则同上。 |
| `created_at` | string | 提交时间，格式 `YYYY-MM-DD HH:MM:SS`（服务器本地时间）。 |

### 1. 获取分组列表

```
GET /api/groups
```

**响应 `200`**

```json
{
  "groups": [
    {
      "id": 1,
      "name1": "张三",
      "name2": "李四",
      "created_at": "2026-09-16 10:00:00"
    }
  ]
}
```

无任何记录时返回 `{"groups": []}`。

### 2. 新增分组

```
POST /api/groups
```

**请求体**

```json
{
  "name1": "张三",
  "name2": "李四"
}
```

**响应 `201`**：返回新建的分组对象（结构见上文"数据结构"）。

**错误响应**

| 状态码 | 响应体 | 触发条件 |
| --- | --- | --- |
| `400` | `{"error": "请求体必须为 JSON 格式"}` | `Content-Type` 不是 `application/json`。 |
| `400` | `{"error": "请填写两位同学的姓名"}` | 任一姓名为空或仅含空白字符。 |
| `400` | `{"error": "同一组内两位同学的姓名不能相同"}` | 两个姓名完全相同。 |
| `500` | `{"error": "数据文件已损坏或无法读取，……"}` | 数据文件异常，写入被拒绝以保护历史数据。 |

**示例**

```bash
curl -X POST http://127.0.0.1:5000/api/groups \
  -H "Content-Type: application/json" \
  -d "{\"name1\":\"张三\",\"name2\":\"李四\"}"
```

### 3. 删除分组

```
DELETE /api/groups/<group_id>
```

**路径参数**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `group_id` | integer | 要删除的分组编号。 |

**响应 `200`**

```json
{
  "ok": true,
  "deleted_id": 1
}
```

**错误响应**

| 状态码 | 响应体 | 触发条件 |
| --- | --- | --- |
| `404` | `{"error": "未找到该分组"}` | 指定编号不存在。 |

### 统一错误响应

对于所有 `/api/` 开头的路径，服务端保证返回 JSON 格式的错误信息：

| 状态码 | 响应体 | 说明 |
| --- | --- | --- |
| `404` | `{"error": "接口不存在"}` | 访问了未定义的 API 路径。 |
| `500` | `{"error": "服务器内部错误"}` | 未预期的服务端异常。 |

非 `/api/` 路径的错误则按 Flask 默认方式处理（返回 HTML 错误页）。

## 数据存储

### 存储格式

全部数据保存在与 `app.py` 同目录的 `groups.json` 中，是一个有序的 JSON 数组：

```json
[
  {
    "id": 1,
    "name1": "张三",
    "name2": "李四",
    "created_at": "2026-09-16 10:00:00"
  },
  {
    "id": 2,
    "name1": "王五",
    "name2": "赵六",
    "created_at": "2026-09-16 10:05:12"
  }
]
```

文件以 UTF-8 编码、`indent=2` 缩进写入，便于直接查看与手工编辑。

### 可靠性设计

为保证数据不丢失，存储层做了三项处理：

**1. 读写共用一把可重入锁（`threading.RLock`）**

`load_data()` 与 `save_data()` 内部各自加锁，因此所有读取路径都受到保护；
`add_group()` / `delete_group()` 这类"读取-修改-写回"的操作会在外层再加一层锁，
确保整个流程不会被并发请求穿插，避免出现"两次提交只保留一条"的写丢失。

**2. 原子写入**

写文件流程为：

```
写入 groups.json.<进程号>.tmp  →  flush  →  os.fsync 落盘  →  os.replace 原子替换
```

- `os.replace` 是原子操作，替换瞬间完成，不存在"文件被写了一半"的中间状态；
- `fsync` 确保数据真正落盘后再替换，断电或崩溃也不会留下空文件；
- 若写入中途出现异常，临时文件会被清理，**原有数据文件保持完全不变**；
- 临时文件名带进程号，即便多进程部署也不会相互覆盖。

**3. 损坏文件隔离**

`load_data()` 严格区分三种情况：

| 情况 | 处理方式 |
| --- | --- |
| 文件不存在 | 返回空列表（首次运行的正常状态）。 |
| 文件存在但 JSON 解析失败 | 备份为 `groups.json.<时间戳>.bak`，抛出 `DataCorruptedError`。 |
| 顶层结构不是数组 | 同上。 |
| 文件无法读取（权限、占用等） | 抛出 `DataCorruptedError`，不伪装成"没有数据"。 |

抛出异常后，API 会返回 `500` 及明确提示，**不会把当前请求写入文件**，
从而彻底杜绝了"文件损坏 → 被当成空数据 → 用一条新记录覆盖全部历史"的连锁数据丢失。

### 备份文件的恢复方法

若目录下出现 `groups.json.20260916-101500.bak` 这类文件，说明检测到过一次数据异常。
恢复步骤如下：

1. 停止服务（在终端按 `Ctrl+C`）。
2. 打开 `.bak` 文件检查内容，手工修复其中明显的 JSON 语法错误（如缺失的括号、逗号）。
3. 将修复后的内容另存为 `groups.json`（覆盖已存在的同名文件）。
4. 确认 `groups.json` 能被 JSON 解析器正常解析后，重新启动服务。


## 导出为 Excel

`export_xlsx.py` 用于把 `groups.json` 导出成 xlsx 表格，方便打印或交给教务系统。
它只读取数据、不修改 `groups.json`，因此可以在服务运行期间随时执行。

### 使用方法

```bash
# 默认：读取同目录的 groups.json，生成同目录的 groups.xlsx
python export_xlsx.py

# 指定输出文件名
python export_xlsx.py -o 分组名单.xlsx

# 指定其它数据文件
python export_xlsx.py D:\备份\groups.json -o D:\备份\分组名单.xlsx

# 查看全部参数
python export_xlsx.py -h
```

### 输出格式

表头固定为 `序号 | 学生1 | 学生2`：

| 序号 | 学生1 | 学生2 |
| --- | --- | --- |
| 1 | 王五 | 赵六 |
| 2 | Alice | Bob |
| 3 | 张三 | 李四 |

说明：

- 记录按原始 `id` 升序排列，`序号` 则按导出顺序从 1 连续编号，因此不会出现跳号；
- `created_at`（提交时间）不写入表格，如需要可自行在 `build_workbook()` 中增加一列；
- 表格已设置表头加粗填充、自适应列宽、冻结首行与自动筛选，可直接在 Excel 中按姓名筛选。

### 异常处理

脚本沿用 `app.py` 的"绝不静默降级"原则：数据文件有问题时**报错并退出（退出码 1）**，
不会生成一张空表让人误以为班级无人填报。

| 情况 | 输出 |
| --- | --- |
| 数据文件不存在 | `导出失败：找不到数据文件：……` |
| JSON 语法错误 | `导出失败：数据文件不是合法的 JSON：……（第 x 行第 y 列）` |
| 顶层结构不是数组 | `导出失败：数据文件格式异常：顶层应为列表……` |
| 某条记录缺少姓名 | `导出失败：第 n 条记录缺少学生姓名……` |
| 输出文件被 Excel 占用 | `导出失败：写入失败：……（若该文件正在 Excel 中打开，请先关闭再重试）` |

数据文件为空（`[]`）不是错误：会正常生成一张只有表头的表格，并提示"共导出 0 条分组记录"。

> 脚本以 `utf-8-sig` 读取数据文件，因此即使 `groups.json` 被记事本等编辑器
> 保存成了带 BOM 的 UTF-8，也能正常解析。

## 常见问题

### Q1：提示"加载数据失败，请确认后端服务已启动"

前端无法访问 `/api/groups`，通常由以下原因导致：

- 后端服务未启动或已崩溃 —— 检查运行 `python app.py` 的终端窗口；
- 访问的是静态文件而非 Flask 服务 —— 请通过 `http://127.0.0.1:5000` 打开，
  不要直接双击 `index.html` 打开（`file://` 协议下无法请求 API）；
- 端口被占用 —— 更换 `port` 后重新访问新地址。

### Q2：页面显示"数据文件已损坏或无法读取"

说明 `groups.json` 无法被解析，程序已自动将其备份并拒绝写入以保护数据。
请查看服务端终端中的日志（会打印备份文件路径），按
[备份文件的恢复方法](#备份文件的恢复方法) 处理。

此时的写入已被暂停，恢复数据文件后服务即可正常使用。

### Q3：局域网内其他设备打不开页面

1. 确认两台设备连接的是同一个局域网；
2. 确认服务监听在 `0.0.0.0` 而非 `127.0.0.1`；
3. 检查 Windows 防火墙是否放行了 Python 或 5000 端口；
4. 在运行服务的电脑上用 `ipconfig` 确认内网 IP 是否正确（注意区分 WLAN 与以太网）。

### Q4：端口 5000 被占用

在 macOS 上 5000 端口常被 AirPlay 占用；Windows 下也可能被其他程序占用。
改用其他端口即可：

```python
app.run(host='0.0.0.0', port=8080, debug=True)
```

同时确保 8080 端口在防火墙中放行。

### Q5：组号为什么会出现不连续？

当前组号由"现有记录的最大 id + 1"计算得出，因此删除末尾记录后再新增，组号会被复用。
例如删除第 3 组后新增，新记录仍是"第 3 组"。如需严格的单调递增编号，
需要额外记录一个自增计数器或改用数据库。

### Q6：能否限制一个同学只能出现在一个组里？

当前不支持。服务端仅校验姓名非空与同组两人不相同，不检查跨组的重复姓名。
如有该需求需在后端补充校验逻辑。

```python
import os

assert resp.status_code == 201
```
